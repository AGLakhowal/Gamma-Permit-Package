What we are doing

We re-derive the authorization decision for every transaction from the Law of Concurrence (Γ = maxᵢ(1−gᵢ)): a permit is granted only when all governance predicates concur. We then score the run against the six LAB v1.0 metrics, the six runtime invariants, and the commit-before-actuate / replay guarantees — and compare our derived decision to the dataset's ground-truth labels.

Non-compensatory gate

No weighted sum or confidence score can offset a failed predicate. One deficit ⇒ Γ>0 ⇒ SAFE_STATE.

How it works — the authorization pipeline

Seven deterministic steps (OL3 boundary). An action enters with zero authority and leaves only through a permit or a logged SAFE_STATE denial.

Γ>0 → SAFE_STATE.

Γ = 0 → ACT_PERMIT

All predicates concur → execute, then the hash-chained ERTuple is sealed. — transactions took this path.

Γ > 0 → SAFE_STATE

Any predicate fails → deny + ERTuple; no externalization. — transactions (all real fraud) took this path.

LAB v1.0 summary (Appendix-A style)

    Reader's questions — answered straight

    The 100% on this page measures the governance machinery, not a fraud detector's skill. Below is exactly what that number means, how it changes when the harm signal is earned rather than borrowed, the full field/predicate mapping, and the bank data that would move the benchmark toward production.

    The accuracy ladder — same gate, three qualities of harm signal

    Why these move and the gate doesn't. The non-compensatory monitor — PERMIT iff max(Γ_G, Γ_class)=0 — is identical in all three rows. Only the quality of the harm signal feeding it changes. The monitor is authorization-sound regardless; detection accuracy is a property of the upstream evidence, not of the gate.

    The 100% is measured on this run. The 65–70% and 85–92% are honest realistic bands for the same gate fed by an earned signal — they are reasoned estimates, not numbers produced by this run.

    1 · Why does the dataset score 100% directly?

    Because the harm signal is the relabeled ground truth. In the mapper each row's harm is 0.8 if Class==1 else ≤0.049, so the decisive deficit HARM_RISK_THETA (harm > θ=0.5) fires on exactly the Class=1 rows, and Gate_A3 / Gate_A7 / Λ_G are set false on those same rows.

    So the gate's verdict and the label are aligned by construction — 100% agreement, 0 false permits, 0 false denials is a tautology on the detection axis.

    What it genuinely proves is the machinery: non-compensatory max never lets a passing predicate offset a harm deficit, the class-veto holds, the SHA-256 chain links 284,807/284,807, replay is deterministic, the gate fails closed. An integrity result, not a detection score.

    tautologicalintegrity proof

    2 · Why does enrichment raise it to ~65–70%?

    Replace the borrowed label with an earned signal: train a real risk model on the dataset's own independent features (V1–V28 PCA components + Amount + Time) and feed its score into HARM_RISK instead of the Class flag. Now the gate must discriminate, not look up the answer.

    On the anonymized ULB features a competent model lands roughly in a 65–70% effective-decision band. The ceiling is the data: V1–V28 are PCA-compressed and de-identified, there is no entity / device / merchant / velocity context, and classes are extreme (492 / 284,807). You can rank risk well, but converting that into clean permit/deny calls at a usable false-positive rate is what caps the band.

    model on V1–V28no entity context

    3 · Why does production reach ~85–92%?

    Deployed card-auth runs on signals this public dataset doesn't contain: raw (un-PCA'd) attributes, device/IP fingerprint, geo + travel velocity, merchant category & history, cardholder behavioral baseline, 3-D Secure / issuer step-up, account tenure, and cross-transaction graph features.

    A model with those inputs is a far stronger discriminator, pushing the harm signal feeding the same gate into the 85–92% band typical of production systems. The governance layer is untouched — only the evidence improves.

    real bank featuresricher evidence

    Card / account / merchant IDs; count & sum over rolling windows.

    Device & network

    Device fingerprint, IP, geolocation, travel-velocity vs prior.

    Merchant context

    Category, risk history, acceptance rate.

    Cardholder baseline

    Behavioral profile, account age / tenure, spend distribution.

    Issuer signals

    3-D Secure outcome, step-up / OTP result, prior chargebacks.

    Labels + latency

    Confirmed-fraud timestamps to model real label delay.

    Graph features

    Shared-device / shared-card linkage across transactions.
